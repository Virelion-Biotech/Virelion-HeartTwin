02 / Getting started

How to use HeartTwin today

For researchers and developers

  1. Read the repository README and installation instructions.
  2. Set up the Python environment and install only the optional components your workflow needs.
  3. Start the HeartTwin API/worker using the repository’s documented configuration.
  4. Open the web workbench and connect it to that worker.
  5. Begin with a small documented example, inspect readiness checks, then record configuration and output provenance.
Repository quick start ↗

For a patient-specific research workflow

  1. Create a pseudonymous case; do not upload identifiable clinical data to a public demo.
  2. Import only data you are authorized to use and document units, coordinate frames and source provenance.
  3. Resolve anatomy/model readiness blockers before running a solver.
  4. Separate calibration data from held-out evaluation data.
  5. Review residuals, uncertainty, failure states and reproducibility—not just a rendered heart.

03 / Evidence & limits

Transparent about what is—and isn’t—ready.

Software integration, numerical verification, data readiness and empirical patient-specific qualification are different gates.

Open research softwareWorker-backed executionProvenance-orientedClinical validation incomplete
  • Some mechanistic paths are phenomenological or reduced-order models rather than fully resolved human physiology.
  • Software and synthetic tests do not establish accuracy on real patient data.
  • Model licensing, data permissions, mesh quality, calibration, held-out validation and uncertainty must be checked for each study.
  • Do not use HeartTwin outputs to diagnose, triage or make treatment decisions.
