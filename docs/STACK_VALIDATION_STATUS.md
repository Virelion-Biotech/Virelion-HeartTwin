# Repository validation and product completion status

Reviewed 2026-10-14. This covers all 29 accessible organization repositories, including the HeartTwin components, discovery programs and supporting tools. Each README has a dated, repository-specific status section with evidence and remaining work. The implementation base identifies inspected code; documentation commits after that base do not imply new algorithm validation.

Software tests, numerical reference checks, data integrity/readiness, empirical endpoint qualification and clinical qualification are different evidence levels. Failed or blocked evidence remains visible. Product completion requires a declared intended scope and acceptance gates; no unsupported percentage is assigned. Infrastructure, game and documentation repositories use appropriate operational/content acceptance rather than fictitious clinical gates.

Use independently controlled splits, references and units of inference appropriate to the endpoint. Check integration versions and deployment operation separately from scientific claims.
