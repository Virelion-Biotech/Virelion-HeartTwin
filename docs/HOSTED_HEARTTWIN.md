# Hosted HeartTwin workspace

HeartTwin is served as one application: the existing workbench UI, authenticated API, job runner, file storage, case store and results are on the same hosted origin. Users do not need to install Python or enter a worker URL.

## One-time owner deployment

1. Deploy the repository’s Render Blueprint: [Create hosted HeartTwin](https://render.com/deploy?repo=https://github.com/Virelion-Biotech/Virelion-HeartTwin).
2. When prompted for `HEARTTWIN_WEB_PASSWORD`, set a strong, unique password of at least 16 characters. Keep it private. `HEARTTWIN_WEB_TOKEN` is generated by Render and must remain a server-side secret.
3. Keep the persistent disk mounted at `/var/data`. The case database, uploads, jobs, logs and result artifacts are written below `/var/data/workspace`.
4. After the service becomes live at `https://hearttwin-virelion.onrender.com`, the GitHub Pages entry point redirects to the application.

The hosted instance runs the versions pinned in `requirements-services.txt`. On startup, HeartTwin exposes which service adapters are installed and runnable; that does not mean every optional external binary, GPU backend, licensed model asset or clinical qualification gate is satisfied.

## Security boundary

This deployment is a **private single-owner research workspace**, not a multi-tenant clinical service. The shared password grants owner-level access to the same cases, uploaded files, executions and artifacts. Do not share it with collaborators or use this deployment for identifiable clinical data. Do not treat process-level job separation as a security sandbox.

Hosted sign-in issues a random in-memory session token that expires after 12 hours and is held in browser memory only. Refreshing the page requires signing in again. Login attempts are rate-limited in memory. The underlying owner token is kept in the server environment and is not sent to the browser.

The persistent disk is a paid Render resource; it is required because an ephemeral filesystem would lose the local SQLite databases and uploaded files on redeploy/restart. This setup does not provide GPU execution. If a specialist adapter requires an external binary or GPU, the UI must show it as unavailable until that runtime is properly provisioned.

## Scope

The public GitHub Pages address is an entry point only. The interactive app is served by the hosted Python service because GitHub Pages cannot execute HeartTwin’s Python/native scientific backends. The initial deployment is a CPU-based research instance. It is not a clinically validated digital twin or a diagnostic/treatment tool.
